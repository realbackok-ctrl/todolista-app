## 발견된 버그

### 🐛 버그 #1: 401 응답 시 에러 메시지 미표시 (심각도: 중)

**영향 시나리오:** SC-01 (잘못된 비밀번호 로그인), SC-10 (현재 비밀번호 불일치)

**원인:** `frontend/src/api/client.js`의 응답 인터셉터가 401 응답 수신 시 **무조건** `window.location.href = '/login'`으로 강제 리다이렉트. 로그인/비밀번호 변경 API 요청의 경우에도 예외 없이 리다이렉트하므로 `onError` 콜백 실행 전 컴포넌트가 언마운트됨.

```js
// 문제 코드 (client.js)
if (error.response?.status === 401) {
  useAuthStore.getState().clearAuth();
  window.location.href = '/login';  // ← 로그인 중인 요청에도 적용됨
}
```

**수정 방안:**
```js
if (error.response?.status === 401) {
  const isAuthEndpoint = error.config?.url?.includes('/auth/login') ||
                         error.config?.url?.includes('/auth/password');
  if (!isAuthEndpoint) {
    useAuthStore.getState().clearAuth();
    window.location.href = '/login';
  }
}
```

### 🐛 버그 #3: 할일 삭제 확인 모달 없음 (심각도: 중)

**영향 시나리오:** SC-07 (할일 삭제)

**원인:** `TodoItem.jsx`의 `handleDelete` 함수가 확인 없이 즉시 `deleteMutation.mutate(todo.id)` 호출. 카테고리 삭제는 모달이 구현되어 있으나 할일 삭제는 누락됨.

**수정 방안:** `TodoItem.jsx`의 `handleDelete`에 확인 모달 추가 (`CategoryItem`과 동일한 패턴 적용).

### 🐛 버그 #4 (신규): SPA 라우팅 미설정 (심각도: 높음)

**영향:** 전체 시나리오 - 직접 URL 접근 및 페이지 새로고침

**원인:** `frontend/vercel.json` 미존재. Vercel은 `/todos`, `/login`, `/register` 등 SPA 하위 경로에 대한 요청을 `index.html`로 fallback하지 않아 `404: NOT_FOUND` 반환.

**증상:**
- 브라우저 새로고침 시 현재 경로 404
- `window.location.href = '/login'`(버그 #1)이 404와 결합되어 복합 오류 발생
- 직접 URL 공유/북마크 불가

**수정 방안:** `frontend/vercel.json` 추가:
```json
{
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://be-kms.vercel.app/api/:path*" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

## 테스트 환경 제약사항

1. **SPA 라우팅 미설정:** 직접 URL 접근 불가. 루트(`/`)로 진입 후 클라이언트 라우팅 또는 `history.pushState`로 우회.
2. **페이지 새로고침 불가:** `location.reload()` 시 현재 경로 404. 루트 재접근으로 우회.
3. **`datetime-local` 입력 제한:** Overdue 할일 생성은 API 직접 호출로 우회. vercel.json 없어 `/api` 프록시 불가, 백엔드 직접 호출 필요.
4. **GlobalPreferences 오버레이:** 로그아웃 버튼 클릭 차단. JS `click()` 직접 호출로 우회.
