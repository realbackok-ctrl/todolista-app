## 발견된 버그

### 🐛 버그 #1: 401 응답 시 에러 메시지 미표시 (심각도: 중)

**영향 시나리오:** SC-01 (잘못된 비밀번호 로그인), SC-10 (현재 비밀번호 불일치)

**원인:** `frontend/src/api/client.js`의 응답 인터셉터가 401 응답 수신 시 **무조건** `window.location.href = '/login'`으로 강제 리다이렉트하여 페이지를 리로드함. 이로 인해 `onError` 콜백이 실행되기 전에 컴포넌트가 언마운트되어 에러 메시지 표시 불가.

```js
// client.js - 문제 코드
apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      useAuthStore.getState().clearAuth();
      window.location.href = '/login';  // ← 항상 리다이렉트 (로그인 중인 경우도 포함)
    }
    return Promise.reject(error);
  }
);
```

**수정 방안:** 이미 `/login` 또는 `/register` 페이지에 있거나, 로그인/비밀번호변경 API 요청인 경우 리다이렉트를 건너뛰고 에러를 그대로 전파.

```js
// 수정 예시
if (error.response?.status === 401) {
  const isAuthEndpoint = error.config?.url?.includes('/auth/login') ||
                         error.config?.url?.includes('/auth/password');
  if (!isAuthEndpoint) {
    useAuthStore.getState().clearAuth();
    window.location.href = '/login';
  }
}
```

### 🐛 버그 #2: 존재하지 않는 할일 ID 접근 시 무한 로딩 (심각도: 중)

**영향 시나리오:** SC-04 (존재하지 않는 할일 접근)

**원인:** `TodoDetailPage`가 404 응답 처리를 하지 않아 로딩 상태에서 멈춤. 시나리오 요구사항은 "존재하지 않는 할일입니다" 메시지 표시 후 목록 화면으로 안내(404).

**수정 방안:** `useTodoQuery`의 에러 상태를 처리하고 404일 경우 에러 메시지 표시 및 `/todos`로 리다이렉트.

---

### 🐛 버그 #3: 할일 삭제 확인 모달 없음 (심각도: 중)

**영향 시나리오:** SC-07 (할일 삭제)

**원인:** `TodoItem.jsx`의 `handleDelete` 함수가 확인 없이 즉시 `deleteMutation.mutate(todo.id)` 호출. 시나리오 요구사항은 "삭제하면 복구할 수 없습니다. 삭제하시겠습니까?" 확인 모달 표시 후 삭제 진행.

카테고리 삭제(`CategoryItem`)는 확인 모달이 구현되어 있으나 할일 삭제는 누락됨.

**수정 방안:** `TodoItem.jsx`의 `handleDelete`에 확인 모달 추가.

## 테스트 환경 제약사항

1. **`datetime-local` 입력 제한:** React의 합성 이벤트 시스템으로 인해 Playwright JavaScript 주입으로 `datetime-local` 값 설정이 React 상태에 반영되지 않음. Overdue 할일 생성은 직접 API 호출로 우회.

2. **GlobalPreferences 오버레이:** 헤더의 Language/Dark 버튼이 다른 버튼 클릭을 차단하는 경우 있음 (`pointer-events` 이슈). JavaScript `click()` 직접 호출로 우회.

3. **Playwright ref 만료:** 스냅샷 이후 DOM 변경 시 ref가 무효화됨. CSS 선택자 또는 JavaScript 평가로 대체.
