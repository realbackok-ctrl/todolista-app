## 1. 프로젝트 개요

### 목적
개인이 할일을 카테고리별로 분류하고, 종료일 및 완료 상태를 기준으로 체계적으로 관리할 수 있는 할일 관리 애플리케이션을 제공한다.

### 문제 배경
- 기존 일정 관리 앱은 카테고리 분류와 종료 시간 표현이 미흡함
- 사용자 맞춤형 카테고리 관리를 지원하는 도구가 부재함

### 목표
- 사용자 인증 기반의 개인화된 할일 관리 환경 제공
- 카테고리 필터링을 통한 할일 목록 효율적 탐색
- 종료일 초과 및 완료 상태를 명확히 구분하여 할일 현황 파악

## 2. 도메인 모델

### 핵심 엔티티

#### User (사용자)
| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| email | String | 로그인 식별자 (유일) |
| password | String | 암호화된 비밀번호 |
| createdAt | DateTime | 가입 일시 |

#### Category (카테고리)
| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| userId | UUID | 소유 사용자 (FK) |
| name | String | 카테고리명 |
| createdAt | DateTime | 생성 일시 |

#### Todo (할일)
| 속속 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| userId | UUID | 소유 사용자 (FK) |
| categoryId | UUID | 분류 카테고리 (FK, nullable) |
| title | String | 할일 제목 |
| description | String | 상세 내용 (optional) |
| status | Enum | 할일 상태 (PENDING / COMPLETED) |
| dueDate | DateTime | 종료 예정 일시 (optional) |
| completedAt | DateTime | 완료 처리 일시 (nullable) |
| createdAt | DateTime | 생성 일시 |
| updatedAt | DateTime | 최종 수정 일시 |

### 엔티티 관계

```
User (1) ──< Category (N)
User (1) ──< Todo (N)
Category (1) ──< Todo (N)   [optional: Todo는 카테고리 없이도 존재 가능]
```

## 3. 핵심 비즈니스 규칙

### [BR-AUTH] 인증 및 권한 규칙
- **BR-AUTH-01:** 모든 기능(할일/카테고리 관리)은 로그인한 사용자만 접근 가능하다.
- **BR-AUTH-02:** 이메일은 시스템 내 유일해야 하며, 중복 등록을 허용하지 않는다.
- **BR-AUTH-03:** 사용자는 자신의 데이터(할일, 카테고리)에 대해서만 CRUD 권한을 가진다.
- **BR-AUTH-04 (탈퇴 정책):** 사용자가 탈퇴할 경우 해당 사용자와 관련된 모든 데이터(카테고리, 할일)는 즉시 영구 삭제(Hard Delete)된다.

### [BR-TODO] 할일 상태 및 전이 규칙
- **BR-TODO-01:** Todo의 status는 `PENDING`(미완료) 또는 `COMPLETED`(완료)만 존재한다. (기본 생성값: `PENDING`)
- **BR-TODO-02:** `COMPLETED` 처리 시 `completedAt`에 현재 시각이 기록되며, `PENDING`으로 복구 시 `null` 처리된다.
- **BR-TODO-03 (기한 초과):** `dueDate`가 현재 시각보다 이전이고 status가 `PENDING`인 경우, 시스템은 이를 **Overdue** 상태로 간주한다.
- **BR-TODO-04 (상태 전이도):**
  ```mermaid
  stateDiagram-v2
      [*] --> PENDING: 생성
      PENDING --> COMPLETED: 완료 처리 (Update Status)
      COMPLETED --> PENDING: 완료 취소 (Re-open)
      PENDING --> Overdue: [조회 시] dueDate < 현재 시각
  ```

### [BR-CAT] 카테고리 규칙
- **BR-CAT-01:** 동일 사용자 내에서 카테고리명은 중복될 수 없다.
- **BR-CAT-02 (삭제 영향):** 카테고리 삭제 시, 해당 카테고리에 속한 모든 Todo의 `categoryId`는 `null`로 업데이트된다 (할일 자체는 삭제되지 않음).

## 4. 주요 유스케이스

### UC-01. 사용자 인증 및 계정
| 항목 | 설명 | 관련 규칙 | 검증 및 에러 시나리오 |
|------|------|-----------|----------------------|
| 회원가입 | 이메일+비밀번호로 계정 생성 | BR-AUTH-02 | 이미 등록된 이메일 사용 시 '중복 오류' 발생 |
| 로그인 | 이메일+비밀번호로 토큰 발급 | BR-AUTH-01 | 일치하지 않는 정보 입력 시 '인증 실패' 오류 발생 |
| 회원탈퇴 | 계정 및 모든 데이터 영구 삭제 | BR-AUTH-04 | 인증되지 않은 요청 시 차단 |

### UC-02. 할일 관리 (Todo Management)
| 항목 | 설명 | 관련 규칙 | 검증 및 에러 시나리오 |
|------|------|-----------|----------------------|
| 할일 생성 | 제목 필수, 나머지 선택 입력 | BR-TODO-01 | 제목이 비어있거나 공백인 경우 생성 실패 |
| 목록 조회 | 필터(상태, 카테고리) 지원 | BR-TODO-03, 04 | 타인의 ID로 할일 조회 시도 시 '권한 없음' 오류 |
| 상태 변경 | 완료 처리 또는 미완료 복구 | BR-TODO-02 | 존재하지 않는 Todo ID 요청 시 '조회 실패' 오류 |
| 할일 삭제 | 해당 할일 영구 삭제 | BR-AUTH-03 | 자신이 생성하지 않은 할일 삭제 시도 시 차단 |

### UC-03. 카테고리 관리 (Category Management)
| 항목 | 설명 | 관련 규칙 | 검증 및 에러 시나리오 |
|------|------|-----------|----------------------|
| 카테고리 생성 | 이름 입력 및 중복 검증 | BR-CAT-01 | 동일 사용자가 이미 동일 이름 사용 중이면 생성 실패 |
| 카테고리 수정 | 이름 변경 및 중복 검증 | BR-CAT-01 | 변경하려는 이름이 이미 존재하면 수정 실패 |
| 카테고리 삭제 | 삭제 후 연결된 Todo 해제 | BR-CAT-02 | 삭제 권한 없는 카테고리 접근 시 '권한 없음' 오류 |

## 5. 용어 사전 (Ubiquitous Language)

| 용어 | 정의 |
|------|------|
| **User (사용자)** | 회원 가입 후 인증된 애플리케이션 이용자 |
| **Todo (할일)** | 사용자가 등록한 처리해야 할 작업 항목 |
| **Category (카테고리)** | 사용자가 직접 정의하는 할일 분류 단위 |
| **PENDING (미완료)** | 아직 처리되지 않은 할일의 기본 상태 |
| **COMPLETED (완료)** | 사용자가 완료 처리한 할일 상태 |
| **Overdue (기한 초과)** | dueDate가 현재 시각 이전이고 PENDING 상태인 할일 |
| **Hard Delete** | 데이터베이스에서 실제 레코드를 완전히 삭제하는 물리적 삭제 |

---

## 6. 미결 사항 및 향후 고려 사항
- **Soft Delete 도입 검토:** 사용자 탈퇴 시 30일간 데이터를 유예 보관한 후 삭제하는 정책에 대한 논의 필요.
- **알림 기능:** `dueDate` 도래 1시간 전 또는 기한 초과 시 사용자에게 푸시 알림을 제공하는 규칙 추가 검토.
- **다국어 지원:** 시스템 기본 카테고리(예: '일상', '업무') 제공 시 다국어 대응 방안.
