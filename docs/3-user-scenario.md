## 1. 문서 개요

본 문서는 TodoList 애플리케이션의 Phase 1 (MVP) 범위에 해당하는 기능 요구사항(FR-AUTH, FR-TODO, FR-CAT)을 사용자 관점의 시나리오로 서술한다. 각 시나리오는 실제 페르소나의 사용 맥락을 바탕으로 작성되었으며, 개발 및 QA팀이 사용자 의도와 시스템 동작을 공통된 기준으로 이해하는 데 목적이 있다.

### 페르소나 요약

| 페르소나 | 이름 | 특성 | 주요 사용 환경 |
|---------|------|------|---------------|
| 페르소나 A | 김철수 (27세, IT 직장인) | 디지털 친숙도 높음, 업무/개인 할일 분리 필요 | 출퇴근 중 모바일 + 업무 중 데스크탑 |
| 페르소나 B | 박소영 (34세, 가정주부) | 디지털 친숙도 중간, 단순하고 빠른 조작 선호 | 모바일 위주, 이동 중 또는 가사 틈틈이 |

## 2. 시나리오 상세

### SC-01. 신규 가입 및 첫 로그인

**페르소나:** 김철수 (페르소나 A)

**목표:** 새 계정을 만들고 앱에 처음 입장한다.

**사전 조건:**
- 김철수는 아직 계정이 없다.
- 앱 회원가입 화면에 접근한 상태이다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 회원가입 화면에서 이메일(`chulsoo@example.com`)과 비밀번호(8자 이상)를 입력하고 가입 버튼을 클릭한다. | 입력값 형식을 검증하고 계정을 생성한다. 가입 완료 메시지를 표시하고 로그인 화면으로 이동한다. |
| 2 | 로그인 화면에서 방금 등록한 이메일과 비밀번호를 입력하고 로그인 버튼을 클릭한다. | 자격증명을 검증하고 인증 토큰을 발급한다. 할일 목록 화면(메인 화면)으로 이동한다. |
| 3 | 메인 화면에 자신의 이름(또는 이메일)이 표시된 빈 할일 목록을 확인한다. | 해당 사용자의 할일 목록(현재 비어 있음)을 표시한다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 이미 등록된 이메일 사용 | 동일 이메일로 가입 시도 | "이미 사용 중인 이메일입니다" 오류 메시지를 표시한다. 가입이 거부된다. (409) |
| 이메일 형식 오류 | 형식에 맞지 않는 이메일 입력 후 가입 시도 | "유효한 이메일 형식을 입력하세요" 안내 메시지를 표시한다. 가입이 진행되지 않는다. |
| 비밀번호 너무 짧음 | 8자 미만 비밀번호 입력 후 가입 시도 | "비밀번호는 최소 8자 이상이어야 합니다" 안내 메시지를 표시한다. 가입이 진행되지 않는다. |
| 잘못된 비밀번호로 로그인 시도 | 틀린 비밀번호 입력 후 로그인 클릭 | "이메일 또는 비밀번호가 올바르지 않습니다" 오류 메시지를 표시한다. 로그인이 거부된다. (401) |

**사후 조건:**
- 김철수의 계정이 시스템에 등록된다.
- 인증 상태가 유지된 채로 메인 화면(할일 목록)에 진입한다.

**관련 FR:** FR-AUTH-01, FR-AUTH-02

### SC-02. 카테고리 생성 및 관리

**페르소나:** 김철수 (페르소나 A)

**목표:** 업무와 개인 생활을 구분하기 위한 카테고리를 만들고, 필요에 따라 이름을 변경하거나 불필요한 카테고리를 삭제한다.

**사전 조건:**
- 김철수는 로그인한 상태이다.
- 아직 생성된 카테고리가 없다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 카테고리 관리 화면으로 이동한다. | 현재 카테고리 목록(비어 있음)을 표시한다. |
| 2 | "카테고리 추가" 버튼을 클릭하고 이름에 "업무"를 입력한 후 저장한다. | 중복 여부를 확인하고 "업무" 카테고리를 생성한다. 목록에 "업무"가 추가된다. |
| 3 | 동일한 방법으로 "개인", "공부" 카테고리를 순서대로 추가한다. | 각 카테고리를 순서대로 생성하고 목록에 표시한다. |
| 4 | "공부" 카테고리 옆의 수정 버튼을 클릭하고 이름을 "자기계발"로 변경한 후 저장한다. | 중복 여부를 확인하고 카테고리명을 "자기계발"로 업데이트한다. 목록에 변경된 이름이 반영된다. |
| 5 | "자기계발" 카테고리 옆의 삭제 버튼을 클릭한다. | 확인 후 카테고리를 삭제한다. 해당 카테고리에 연결되어 있던 할일들의 카테고리 분류는 해제되지만(미분류 상태), 할일 자체는 유지된다. |
| 6 | 카테고리 목록을 다시 확인한다. | "업무", "개인" 두 개의 카테고리만 목록에 표시된다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 중복 이름으로 카테고리 생성 시도 | 이미 존재하는 "업무"라는 이름으로 카테고리 추가 시도 | "이미 사용 중인 카테고리 이름입니다" 오류 메시지를 표시한다. 생성이 거부된다. (409) |
| 중복 이름으로 카테고리 수정 시도 | 기존 카테고리명을 이미 존재하는 이름으로 변경 시도 | "이미 사용 중인 카테고리 이름입니다" 오류 메시지를 표시한다. 수정이 거부된다. (409) |
| 이름 입력 없이 저장 시도 | 이름 입력 필드를 비워두거나 공백만 입력 후 저장 | "카테고리 이름을 입력해 주세요" 안내 메시지를 표시한다. 저장이 진행되지 않는다. (400) |

**사후 조건:**
- "업무", "개인" 카테고리가 김철수의 계정에 등록된다.
- 삭제된 카테고리에 연결되었던 할일들은 카테고리 미분류 상태로 유지된다.

**관련 FR:** FR-CAT-01, FR-CAT-02, FR-CAT-03, FR-CAT-04

### SC-03. 할일 생성 및 목록 조회

**페르소나:** 박소영 (페르소나 B)

**목표:** 오늘 해야 할 일들을 앱에 빠르게 등록하고, 종류별로 분류하여 한눈에 확인한다.

**사전 조건:**
- 박소영은 로그인한 상태이다.
- "가사", "육아", "개인" 카테고리가 이미 생성되어 있다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 메인 화면에서 "할일 추가" 버튼을 클릭한다. | 할일 입력 폼을 표시한다. |
| 2 | 제목에 "마트 장보기"를 입력하고, 카테고리로 "가사"를 선택하고, 종료일을 오늘 오후 6시로 설정한 후 저장한다. | 할일을 PENDING 상태로 생성하고 목록에 추가한다. |
| 3 | 다시 "할일 추가"를 클릭하여 제목에 "어린이집 하원 준비"를 입력하고 카테고리로 "육아"를 선택하고 저장한다. (종료일 미입력) | 종료일 없이 PENDING 상태로 할일을 생성하고 목록에 추가한다. |
| 4 | 또다시 "할일 추가"를 클릭하여 제목에 "병원 예약 확인"을 입력하고 카테고리는 선택하지 않고 저장한다. | 카테고리 미분류 상태로 PENDING 상태 할일을 생성하고 목록에 추가한다. |
| 5 | 전체 할일 목록에서 세 개의 할일이 모두 표시되는 것을 확인한다. | 박소영 소유의 할일 목록 전체를 표시한다. 각 할일의 상태(PENDING), 카테고리, 종료일이 함께 표시된다. |
| 6 | 카테고리 필터에서 "가사"를 선택한다. | 카테고리가 "가사"인 할일만 필터링하여 목록에 표시한다. "마트 장보기"만 보인다. |
| 7 | 필터를 "전체"로 초기화한다. | 모든 할일을 다시 목록에 표시한다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 제목 없이 저장 시도 | 제목 필드를 비워두고 저장 버튼 클릭 | "할일 제목을 입력해 주세요" 안내 메시지를 표시한다. 저장이 진행되지 않는다. (400) |
| 공백만 제목으로 저장 시도 | 제목 필드에 공백만 입력하고 저장 버튼 클릭 | "유효한 제목을 입력해 주세요" 안내 메시지를 표시한다. 저장이 진행되지 않는다. (400) |

**사후 조건:**
- 박소영의 할일 세 건이 모두 PENDING 상태로 등록된다.
- 카테고리 필터가 즉시 반영되어 목록이 갱신된다.

**관련 FR:** FR-TODO-01, FR-TODO-02

### SC-04. 할일 상세 조회 및 수정

**페르소나:** 김철수 (페르소나 A)

**목표:** 등록해 둔 업무 할일의 내용을 확인하고, 마감일이 변경되어 종료일을 수정한다.

**사전 조건:**
- 김철수는 로그인한 상태이다.
- "업무" 카테고리와 "분기 보고서 작성"이라는 할일이 이미 등록되어 있다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 할일 목록에서 "분기 보고서 작성"을 클릭하여 상세 화면으로 진입한다. | 해당 할일의 전체 정보(제목, 설명, 카테고리, 종료일, 현재 상태, 생성일 등)를 표시한다. |
| 2 | 상세 화면에서 수정 버튼을 클릭한다. | 현재 입력 값이 채워진 수정 폼을 표시한다. |
| 3 | 설명란에 "팀장 검토 포함 일정 여유 확보 필요"를 추가 입력하고, 종료일을 기존 일자에서 이틀 뒤로 변경한 후 저장한다. | 변경된 내용을 저장하고 상세 화면에 반영한다. 수정 완료 안내 메시지를 표시한다. |
| 4 | 상세 화면에서 변경된 설명과 종료일이 올바르게 표시되는지 확인한다. | 업데이트된 데이터를 정확하게 표시한다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 제목을 지우고 저장 시도 | 수정 폼에서 제목을 빈 값으로 만들고 저장 클릭 | "할일 제목을 입력해 주세요" 안내 메시지를 표시한다. 저장이 진행되지 않는다. (400) |
| 존재하지 않는 할일 접근 | URL을 직접 입력하여 존재하지 않는 할일 ID에 접근 | "존재하지 않는 할일입니다" 오류 메시지를 표시하고 목록 화면으로 안내한다. (404) |

**사후 조건:**
- "분기 보고서 작성" 할일의 설명과 종료일이 수정된 내용으로 저장된다.

**관련 FR:** FR-TODO-03, FR-TODO-04

### SC-05. 할일 완료 처리 및 복구

**페르소나:** 박소영 (페르소나 B)

**목표:** 마트 장보기를 마치고 해당 할일을 완료 처리한다. 이후 추가 구매가 필요함을 깨닫고 완료를 취소하여 미완료 상태로 되돌린다.

**사전 조건:**
- 박소영은 로그인한 상태이다.
- "마트 장보기" 할일이 PENDING 상태로 목록에 존재한다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 할일 목록에서 "마트 장보기" 항목의 완료 체크 버튼을 탭한다. | 해당 할일의 상태를 COMPLETED로 변경하고 완료 처리 시각을 기록한다. 할일 항목이 완료 표시(색상 또는 아이콘 변경)로 즉시 업데이트된다. |
| 2 | 상태 필터를 "완료"로 변경하여 완료된 할일만 본다. | COMPLETED 상태의 할일만 표시한다. "마트 장보기"가 완료 목록에 표시된다. |
| 3 | "마트 장보기" 항목을 다시 클릭하여 완료 처리를 취소(미완료 복구)한다. | 해당 할일의 상태를 다시 PENDING으로 변경하고 완료 시각 기록을 삭제한다. 완료 표시가 해제된다. |
| 4 | 필터를 "전체"로 변경하여 목록을 확인한다. | "마트 장보기"가 PENDING 상태로 목록에 다시 표시된다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 네트워크 오류 발생 | 상태 변경 버튼을 탭했으나 응답이 없는 경우 | 오류 안내 메시지를 표시하고 화면의 상태를 변경 전으로 유지한다. 재시도를 안내한다. |

**사후 조건:**
- "마트 장보기" 할일은 PENDING 상태로 되돌아가며, 완료 시각 정보는 초기화된다.

### SC-06. Overdue 할일 식별 및 처리

**페르소나:** 김철수 (페르소나 A)

**목표:** 출근 후 앱을 열어 마감이 지난 할일을 즉시 확인하고 우선순위를 파악한다.

**사전 조건:**
- 김철수는 로그인한 상태이다.
- 종료일이 어제로 설정되어 있고 PENDING 상태인 "주간 회의 자료 준비" 할일이 존재한다.
- 종료일이 오늘 오후로 설정되어 있고 PENDING 상태인 "코드 리뷰 완료" 할일이 존재한다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 앱을 열어 할일 목록 화면에 진입한다. | 할일 목록을 표시한다. 종료일이 현재 시각보다 이전이고 PENDING 상태인 "주간 회의 자료 준비"는 Overdue 표시(예: 빨간색 강조, 경고 아이콘)로 구분된다. "코드 리뷰 완료"는 일반 PENDING 표시로 나타난다. |
| 2 | Overdue 표시된 "주간 회의 자료 준비"를 확인하고, 해당 항목을 클릭하여 상세 내용을 확인한다. | 해당 할일의 상세 정보(제목, 종료일, 현재 상태)를 표시한다. |
| 3 | 즉시 처리할 수 없어 종료일을 오늘 오후로 수정한다. | 종료일을 업데이트한다. 현재 시각이 아직 새로운 종료일 이전이므로 Overdue 표시가 해제되고 일반 PENDING 상태로 표시된다. |
| 4 | 목록으로 돌아와 두 할일 모두 일반 PENDING 상태로 표시되는지 확인한다. | 두 할일 모두 Overdue 표시 없이 PENDING 상태로 표시된다. |
| 5 | "코드 리뷰 완료" 할일을 완료 처리한다. | 해당 할일의 상태를 COMPLETED로 변경하고 완료 처리 시각을 기록한다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 상태 필터 "미완료"로 조회 | 필터를 "미완료(PENDING)"로 설정하여 조회 | PENDING 상태의 할일만 표시하며, Overdue 해당 항목은 여전히 Overdue 시각 표시를 함께 적용한다. |

**사후 조건:**
- "주간 회의 자료 준비"의 종료일이 갱신되어 Overdue 상태에서 벗어난다.
- "코드 리뷰 완료"는 COMPLETED 상태로 기록된다.

**관련 FR:** FR-TODO-02, FR-TODO-05

### SC-07. 할일 삭제

**페르소나:** 박소영 (페르소나 B)

**목표:** 더 이상 필요하지 않은 할일을 목록에서 영구적으로 제거한다.

**사전 조건:**
- 박소영은 로그인한 상태이다.
- "병원 예약 확인" 할일이 목록에 존재한다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 할일 목록에서 "병원 예약 확인" 항목의 삭제 버튼을 탭한다. | 삭제 여부를 재확인하는 안내 메시지(예: "삭제하면 복구할 수 없습니다. 삭제하시겠습니까?")를 표시한다. |
| 2 | 삭제 확인 버튼을 탭한다. | 해당 할일을 영구 삭제(Hard Delete)한다. 할일 목록에서 해당 항목이 즉시 제거된다. |
| 3 | 목록을 확인하여 "병원 예약 확인"이 사라진 것을 확인한다. | 삭제된 할일이 목록에 표시되지 않는다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 삭제 취소 | 삭제 확인 안내에서 "취소" 버튼을 탭 | 삭제를 진행하지 않고 기존 목록 화면으로 돌아간다. 할일은 유지된다. |
| 다른 사용자의 할일 삭제 시도 | URL 조작 등으로 타인 소유 할일 삭제 요청 | "접근 권한이 없습니다" 오류 메시지를 표시한다. 삭제가 거부된다. (403) |
| 이미 삭제된 할일 삭제 재시도 | 이미 삭제 처리된 할일 ID로 삭제 재요청 | "존재하지 않는 할일입니다" 오류 메시지를 표시한다. (404) |

**사후 조건:**
- "병원 예약 확인" 할일이 시스템에서 완전히 삭제되며 복구할 수 없다.

### SC-08. 로그아웃 및 재로그인

**페르소나:** 박소영 (페르소나 B)

**목표:** 가족이 기기를 사용할 수 있어 앱에서 로그아웃하고, 이후 본인이 다시 로그인하여 할일을 확인한다.

**사전 조건:**
- 박소영은 현재 로그인한 상태이다.
- 할일 목록에 여러 건의 할일이 등록되어 있다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 앱 설정 또는 메뉴에서 로그아웃 버튼을 탭한다. | 클라이언트에 저장된 인증 토큰을 폐기한다. 로그인 화면으로 이동한다. |
| 2 | 로그아웃 상태에서 할일 목록 URL에 직접 접근을 시도한다. | 인증되지 않은 요청을 차단하고 로그인 화면으로 리다이렉트한다. (401) |
| 3 | 로그인 화면에서 이메일과 비밀번호를 입력하고 로그인한다. | 자격증명을 검증하고 새 인증 토큰을 발급한다. 할일 목록 화면으로 이동한다. |
| 4 | 목록에서 기존에 등록된 할일들이 그대로 유지되어 있는지 확인한다. | 박소영 소유의 할일 목록 전체를 표시한다. |

**사후 조건:**
- 로그아웃 후 인증 토큰이 무효화되어 보호된 기능에 접근할 수 없다.
- 재로그인 후 박소영의 데이터는 그대로 유지된다.

**관련 FR:** FR-AUTH-02, FR-AUTH-03, FR-CMN-01

### SC-09. 회원탈퇴

**페르소나:** 김철수 (페르소나 A)

**목표:** 앱 사용을 중단하기로 결정하고 계정과 모든 데이터를 완전히 삭제한다.

**사전 조건:**
- 김철수는 로그인한 상태이다.
- "업무", "개인" 카테고리와 여러 건의 할일이 등록되어 있다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 계정 설정 화면에서 회원탈퇴 버튼을 클릭한다. | 탈퇴 시 모든 데이터(할일, 카테고리)가 영구 삭제된다는 안내 메시지와 재확인 요청을 표시한다. |
| 2 | 안내 내용을 확인하고 최종 탈퇴 확인 버튼을 클릭한다. | 김철수의 계정, 모든 카테고리, 모든 할일을 즉시 영구 삭제(Hard Delete)한다. 로그인 화면으로 이동하며 탈퇴 완료 메시지를 표시한다. |
| 3 | 탈퇴 후 동일 이메일로 로그인을 시도한다. | "이메일 또는 비밀번호가 올바르지 않습니다" 오류를 반환한다. (401) 계정이 존재하지 않으므로 로그인이 불가능하다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 탈퇴 취소 | 재확인 안내에서 "취소" 버튼 클릭 | 탈퇴를 진행하지 않고 계정 설정 화면으로 돌아간다. |
| 비인증 상태에서 탈퇴 시도 | 로그인 없이 탈퇴 API를 직접 요청 | 인증되지 않은 요청을 차단한다. (401) |

**사후 조건:**
- 김철수의 계정, 카테고리, 할일 전체가 데이터베이스에서 완전히 삭제된다. 복구할 수 없다.
- 동일 이메일로 신규 가입은 가능하다. (기존 데이터와 연결 없음)

**관련 FR:** FR-AUTH-04

### SC-10. 비밀번호 변경

**페르소나:** 박소영 (페르소나 B)

**목표:** 보안을 위해 현재 사용 중인 비밀번호를 새 비밀번호로 변경한다.

**사전 조건:**
- 박소영은 로그인한 상태이다.
- 현재 비밀번호를 알고 있다.

**주요 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 1 | 계정 설정 화면에서 "비밀번호 변경" 메뉴를 탭한다. | 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인 입력 폼을 표시한다. |
| 2 | 현재 비밀번호를 입력하고, 새 비밀번호(8자 이상)와 동일한 값을 확인란에 입력한 후 변경 버튼을 탭한다. | 현재 비밀번호의 일치 여부를 검증하고, 새 비밀번호를 암호화하여 저장한다. "비밀번호가 변경되었습니다" 완료 메시지를 표시한다. |
| 3 | 완료 후 로그아웃되어 로그인 화면으로 이동하는지 확인한다. | 보안을 위해 기존 인증 토큰을 폐기하고 로그인 화면으로 이동한다. |
| 4 | 새 비밀번호로 다시 로그인한다. | 자격증명을 검증하고 새 인증 토큰을 발급한다. 할일 목록 화면으로 이동한다. |

**예외/대안 흐름:**

| 상황 | 사용자 행동 | 시스템 응답 |
|------|-----------|-----------|
| 현재 비밀번호 불일치 | 현재 비밀번호를 잘못 입력하고 변경 시도 | "현재 비밀번호가 올바르지 않습니다" 오류 메시지를 표시한다. 변경이 거부된다. (401) |
| 새 비밀번호 확인 불일치 | 새 비밀번호와 확인란의 값이 다른 상태로 변경 시도 | "새 비밀번호가 일치하지 않습니다" 안내 메시지를 표시한다. 변경이 진행되지 않는다. (400) |
| 새 비밀번호 길이 미달 | 8자 미만의 새 비밀번호 입력 후 변경 시도 | "비밀번호는 최소 8자 이상이어야 합니다" 안내 메시지를 표시한다. 변경이 진행되지 않는다. (400) |
| 현재 비밀번호와 동일한 새 비밀번호 | 기존과 동일한 값으로 변경 시도 | "현재 비밀번호와 다른 비밀번호를 입력해 주세요" 안내 메시지를 표시한다. 변경이 거부된다. (400) |

**사후 조건:**
- 박소영의 비밀번호가 새 비밀번호로 변경되어 저장된다.
- 기존 인증 토큰이 폐기되고, 새 비밀번호로 재로그인해야 한다.

**관련 FR:** FR-AUTH-05
