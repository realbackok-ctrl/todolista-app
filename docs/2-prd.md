## 1. 문서 개요

### 목적
본 문서는 TodoList 애플리케이션의 Phase 1 (MVP) 개발을 위한 제품 요구사항을 정의한다. 기획, 개발, QA 등 모든 팀원이 공통된 이해를 바탕으로 제품을 구현할 수 있도록 기능 요구사항, 비기능 요구사항, 기술 제약사항, 개발 일정을 명확히 기술한다.

### 적용 범위
- Phase 1 MVP 범위에 한정하여 기술한다.
- 도메인 정의서(`1-domain-definition.md`)의 비즈니스 규칙(BR) 및 유스케이스(UC) 코드를 기준으로 요구사항을 추적한다.

## 2. 제품 개요

### 제품 목적
개인이 할일을 카테고리별로 분류하고, 종료일 및 완료 상태를 기준으로 체계적으로 관리할 수 있는 할일 관리 웹 애플리케이션이다.

### 문제 정의
| 문제 | 설명 |
|------|------|
| 카테고리 분류 미흡 | 기존 일정 관리 앱은 사용자 맞춤형 카테고리 분류를 지원하지 않아 할일이 뒤섞여 관리가 어렵다 |
| 기한 표현 불명확 | 종료 시간이 지난 미완료 할일을 명시적으로 구분하는 기능이 부재하여 긴급도를 파악하기 어렵다 |
| 개인화 부족 | 개인 계정 기반의 데이터 분리가 이루어지지 않아 보안 및 프라이버시 우려가 존재한다 |

### 제품 목표
- 사용자 인증 기반의 개인화된 할일 관리 환경을 제공한다.
- 카테고리 필터링을 통해 할일 목록을 효율적으로 탐색할 수 있도록 한다.
- 기한 초과(Overdue) 및 완료(COMPLETED) 상태를 명확히 구분하여 할일 현황을 한눈에 파악할 수 있도록 한다.

## 4. 기능 요구사항

> 기능 ID 체계: `FR-{도메인}-{번호}` (FR: Functional Requirement)
> 우선순위: P1 (필수, MVP), P2 (중요), P3 (선택)

### 4.1 사용자 인증 및 계정 관리 (UC-01 참조)

| 기능 ID | 기능명 | 설명 | 우선순위 | 관련 BR/UC |
|---------|--------|------|----------|------------|
| FR-AUTH-01 | 회원가입 | 이메일과 비밀번호를 입력하여 신규 계정을 생성한다. 이미 등록된 이메일은 거부한다. | P1 | BR-AUTH-02, UC-01 |
| FR-AUTH-02 | 로그인 | 등록된 이메일과 비밀번호로 인증 후 JWT 토큰을 발급받는다. | P1 | BR-AUTH-01, UC-01 |
| FR-AUTH-03 | 로그아웃 | 클라이언트에서 JWT 토큰을 폐기하여 세션을 종료한다. | P1 | BR-AUTH-01 |
| FR-AUTH-04 | 회원탈퇴 | 인증된 사용자가 계정을 삭제한다. 계정과 연결된 모든 할일 및 카테고리 데이터를 즉시 영구 삭제(Hard Delete)한다. | P1 | BR-AUTH-04, UC-01 |
| FR-AUTH-05 | 비밀번호 변경 | 로그인한 사용자가 현재 비밀번호를 확인한 후 새 비밀번호로 변경한다. 변경 완료 후 기존 인증 토큰을 폐기하고 재로그인을 요구한다. | P1 | BR-AUTH-01, UC-01 |

**입력 유효성 검증 규칙:**
- 이메일: 유효한 이메일 형식 (RFC 5322 준수)
- 비밀번호: 최소 8자 이상 (상세 정책은 기술 구현 단계에서 확정)
- FR-AUTH-01 에러: 중복 이메일 사용 시 `409 Conflict` 반환
- FR-AUTH-02 에러: 이메일 또는 비밀번호 불일치 시 `401 Unauthorized` 반환
- FR-AUTH-05 에러: 현재 비밀번호 불일치 시 `401 Unauthorized` 반환, 새 비밀번호 확인 불일치·길이 미달·현재 비밀번호와 동일한 경우 `400 Bad Request` 반환

### 4.2 할일 관리 (UC-02 참조)

| 기능 ID | 기능명 | 설명 | 우선순위 | 관련 BR/UC |
|---------|--------|------|----------|------------|
| FR-TODO-01 | 할일 생성 | 제목(필수), 설명(선택), 카테고리(선택), 종료 예정 일시(선택)를 입력하여 할일을 생성한다. 초기 상태는 PENDING이다. | P1 | BR-TODO-01, UC-02 |
| FR-TODO-02 | 할일 목록 조회 | 로그인한 사용자의 할일 목록을 조회한다. 상태(PENDING/COMPLETED) 및 카테고리 기준 필터링을 지원한다. Overdue 상태는 조회 시 클라이언트에서 식별 가능하도록 표시한다. | P1 | BR-TODO-03, BR-TODO-04, UC-02 |
| FR-TODO-03 | 할일 상세 조회 | 특정 할일의 모든 속성(제목, 설명, 상태, 종료일, 완료일 등)을 조회한다. | P1 | BR-AUTH-03, UC-02 |
| FR-TODO-04 | 할일 수정 | 할일의 제목, 설명, 카테고리, 종료 예정 일시를 수정한다. | P1 | BR-AUTH-03, UC-02 |
| FR-TODO-05 | 할일 상태 변경 | PENDING 상태의 할일을 COMPLETED로 처리하거나, COMPLETED 상태를 PENDING으로 복구한다. COMPLETED 처리 시 completedAt에 현재 시각을 기록하고, PENDING 복구 시 completedAt을 null로 초기화한다. | P1 | BR-TODO-02, UC-02 |
| FR-TODO-06 | 할일 삭제 | 선택한 할일을 영구 삭제(Hard Delete)한다. 본인 소유 할일만 삭제 가능하다. | P1 | BR-AUTH-03, UC-02 |

**Overdue 식별 규칙 (BR-TODO-03):**
- `dueDate < 현재 시각` 이고 `status = PENDING` 인 경우 Overdue로 간주
- Overdue는 별도 DB 상태값이 아닌, 조회 시점에 클라이언트가 판단하여 시각적으로 구분 표시

**입력 유효성 검증 규칙:**
- 제목: 공백만으로 구성되거나 비어있는 경우 생성/수정 실패 (`400 Bad Request`)
- 타인 소유 할일 접근 시 `403 Forbidden` 반환
- 존재하지 않는 할일 ID 요청 시 `404 Not Found` 반환

### 4.3 카테고리 관리 (UC-03 참조)

| 기능 ID | 기능명 | 설명 | 우선순위 | 관련 BR/UC |
|---------|--------|------|----------|------------|
| FR-CAT-01 | 카테고리 생성 | 카테고리 이름을 입력하여 생성한다. 동일 사용자 내 중복 이름은 거부한다. | P1 | BR-CAT-01, UC-03 |
| FR-CAT-02 | 카테고리 목록 조회 | 로그인한 사용자의 카테고리 목록을 조회한다. | P1 | BR-AUTH-03, UC-03 |
| FR-CAT-03 | 카테고리 수정 | 카테고리 이름을 변경한다. 변경 후 이름이 동일 사용자 내 중복이면 거부한다. | P1 | BR-CAT-01, UC-03 |

**입력 유효성 검증 규칙:**

- 동일 사용자 내 중복 이름 사용 시 `409 Conflict` 반환
- 타인 소유 카테고리 접근 시 `403 Forbidden` 반환

## 5. 비기능 요구사항

### 5.1 성능

| 항목 | 요구사항 |
|------|----------|
| API 응답 시간 | 일반 CRUD 요청의 95th percentile 응답 시간 500ms 이내 |
| 페이지 초기 로딩 | 주요 화면 첫 렌더링(LCP) 3초 이내 |
| 동시 사용자 | Phase 1에서는 소규모 개인 사용자 대상이므로 별도 부하 테스트 목표치 없음 (추후 Phase 2에서 정의) |

### 5.2 보안

| 항목 | 요구사항 |
|------|----------|
| 인증 방식 | JWT (HS-512 알고리즘) 기반 Stateless 인증 |
| 비밀번호 저장 | 단방향 암호화(bcrypt 등) 처리 후 저장, 평문 저장 금지 |
| 데이터 접근 | 모든 API는 소유자 검증 후 데이터 반환 (BR-AUTH-03) |
| 통신 보안 | HTTPS 통신 적용 (배포 환경 기준) |
| SQL Injection 방지 | pg 라이브러리의 Parameterized Query 사용 |

### 5.3 호환성

| 항목 | 요구사항 |
|------|----------|
| 플랫폼 | 반응형 웹 - 모바일(375px 이상) 및 데스크탑(1280px 이상) 대응 |
| 브라우저 | Chrome 최신 버전, Safari 최신 버전, Edge 최신 버전 지원 |
| 해상도 | 모바일 / 태블릿 / 데스크탑 3개 브레이크포인트 Tailwind CSS 기준 적용 |

### 5.4 사용성

| 항목 | 요구사항 |
|------|----------|
| Overdue 시각화 | 기한 초과 할일은 목록에서 일반 할일과 시각적으로 명확히 구분 표시 |
| 상태 구분 | PENDING / COMPLETED / Overdue 상태를 색상 또는 아이콘으로 즉시 식별 가능 |
| 필터 UX | 상태 및 카테고리 필터는 한 화면 내에서 즉시 적용 (페이지 이동 없이) |

### 5.5 데이터 무결성

| 항목 | 요구사항 |
|------|----------|
| 연쇄 삭제 | 회원 탈퇴 시 해당 사용자의 카테고리, 할일 모두 즉시 Hard Delete (BR-AUTH-04) |
| 카테고리 삭제 | 카테고리 삭제 시 연결된 할일의 categoryId를 null로 업데이트 (BR-CAT-02) |
| 상태 일관성 | completedAt은 COMPLETED 상태일 때만 값을 가지며, PENDING 상태에서는 반드시 null (BR-TODO-02) |
